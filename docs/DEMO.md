# Проверка AI Sana Challenge Hub

## Запуск

```bash
python3 server.py
Открыть:
http://127.0.0.1:8765
Основной сквозной сценарий
1. Создание задачи бизнесом
1. Выбрать роль «Бизнес».
2. Нажать «Создать задачу».
3. Ввести короткое описание или использовать демо-пример.
4. Нажать «Уточнить задачу».
Система анализирует недостающие сведения и формирует минимум 3 релевантных уточняющих вопроса.
AI не добавляет факты, которых не предоставил пользователь.
2. Уточнение задачи
Пользователь отвечает на вопросы вручную либо использует демонстрационные ответы.
Пример:
- Потребность: Снизить списания и рассчитывать объём закупок на следующий день.
- Пользователи: Управляющий кофейней и сотрудник, оформляющий закупки.
- Данные: Обезличенные CSV продаж и списаний за 6 месяцев.
- Ограничения: Три недели; локальный прототип; без подключения к кассе и персональных данных.
- Результат: Панель с прогнозом спроса по категориям на следующий день.
- Критерии успеха: MAE ниже среднего за последние 7 дней.
- Контакт: coffee@example.com.
- Формат взаимодействия: Созвон каждый вторник; ответы на вопросы в течение двух рабочих дней.
3. Рейтинг готовности
Карточка получает рейтинг от 0 до 100.
Критерий	Баллы
Контекст	10
Потребность	10
Данные и материалы	20
Ожидаемый результат	15
Критерии успеха	15
Ограничения	10
Пользователи	10
Контакт	5
Формат взаимодействия	5
Всего	100


Уровни готовности:
- 0–39 — Черновик
- 40–69 — Рабочая
- 70–89 — Готовая
- 90–100 — Приоритетная
До подтверждения бизнесом рейтинг является предварительным.
После изменения сведений подтверждение снимается.
4. Публикация
Для публикации бизнес:
1. проверяет карточку;
2. подтверждает сведения;
3. нажимает «Подтвердить и опубликовать».
Слабая задача также может быть опубликована.
Низкий рейтинг не запрещает студентам откликаться.
5. Каталог
После публикации задача появляется в общем каталоге.
Основной принцип:
чем выше рейтинг готовности задачи, тем выше её позиция в каталоге.
При одинаковом рейтинге более новые карточки отображаются выше.
Главная геймификация направлена на бизнес и мотивирует подробнее описывать реальные задачи.
6. Отклик студента
1. Переключить роль на «Студент».
2. Открыть опубликованную задачу.
3. Выбрать команду.
4. Заполнить отклик.
Пример:
Идея
Сравним простой прогноз со средним за неделю и покажем рекомендуемый объём закупок по категориям.
План
Неделя 1: проверка CSV.
Неделя 2: базовый прогноз и оценка ошибки.
Неделя 3: панель и демонстрация.
Срок
3 недели.
Ссылка
https://example.com/nomad-prototype
После отправки отклик появляется в разделе «Мои отклики» со статусом «На рассмотрении».
7. Решение бизнеса
1. Переключить роль на «Бизнес».
2. Открыть задачу.
3. Просмотреть предложения команд.
4. Выбрать «Выбрать команду» или «Отклонить».
Решение принимает бизнес вручную.
Система:
- не назначает исполнителей автоматически;
- не скрывает команды;
- не ограничивает студентам доступ к каталогу.
Можно рассмотреть несколько предложений.
AI-функция
В MVP используется локальный AI-режим.
Он:
- анализирует незаполненные сведения;
- формирует уточняющие вопросы;
- возвращает структурированный результат;
- не добавляет неизвестные факты.
Контракт описан в:
docs/AI-CONTRACT.md
Внешняя LLM может быть подключена через тот же серверный контракт без изменения основного пользовательского сценария.
Дополнительная проверка
Проверить, что:
- без подтверждения публикация блокируется;
- после изменения карточки подтверждение снимается;
- рейтинг пересчитывается;
- слабая опубликованная задача остаётся доступной;
- поиск работает;
- фильтры работают;
- при отсутствии результатов отображается пустое состояние;
- студент может отправить отклик;
- бизнес может принять или отклонить предложение;
- после обновления страницы данные сохраняются.
Ограничения MVP
В рамках пятичасового хакатона намеренно не реализованы:
- полноценная регистрация;
- восстановление пароля;
- сложная ролевая модель;
- realtime-чат;
- уведомления;
- календарь;
- файловое хранилище;
- собственная ML-модель;
- векторная база данных;
- мобильная адаптация;
- production-инфраструктура;
- полный проектный трекер.
Для проверки реализован основной сценарий:
черновик → AI-уточнение → карточка → рейтинг → каталог → отклик → решение бизнеса.
Ключевой принцип
Главная геймификация направлена на бизнес:
Чем полнее и полезнее описана задача, тем выше её рейтинг и позиция в каталоге.

Система может рекомендовать задачи студентам, но не назначает команды.
